# Geometry update candidates · source-only diagnosis · 2026-10-04

The initial investigation used current source and the existing `process-review-2026-10-04/evidence/playback-summary.json` aggregation only. It ran no model, test, benchmark or browser. The previous 84-process playback aggregate ranks meiosis fourth by update p95: apoptosis 21.0 ms, differentiation 17.5, autophagy 14.8, **meiosis 13.1**. Meiosis median update is 4.3 ms, p95 interval 18.4 ms, max interval 45.1 ms; mitosis is 1.4 ms update p95 and infection 2.1 ms. These are previous local measurements under uncontrolled concurrent load, not a new baseline or function-level profile. Function priorities below are source-based inferences.

## Highest-confidence candidates selected by root

### 1. Remove the intermediate zero deformation in meiosis

`meiosisProcess.js:update`, current `c.setDeflection(0)` followed by `axisPoint(exchangeY)` and then `setDeflection(d)`, drives `divisionShapes.js:chromatid.setDeflection` twice for each of four recombinant chromatids whenever the final deformation is nonzero. Each call regenerates three arm meshes, recomputes their indexed normals/bounds, and reconstructs six decorative instance arrays (three paths × 168 segments and three nucleosome sets × 60 instances). Resetting to zero also defeats the existing `lastDeflection` cache on constant-deformation plateaus.

Add a read-only `restAxisPoint(y)` that uses the identical local-to-world then world-to-model arithmetic with zero displacement, without changing any geometry. Compute `d` from it and call `setDeflection(d)` once. The final setter is a pure construction from retained original arrays plus absolute `d`, so removing the unused intermediate geometry preserves the final positions, normals, instance matrices and bounds. Complexity changes from up to two O(vertices + triangles + instances) rebuilds per recombinant per update to one, or zero on exact-value plateaus. Do not replace the world/local roundtrip with a mathematically cancelled matrix: that can alter floating-point rounding.

Validation: compare full geometry positions/normals, all instance matrices, transforms, bounds, materials, visibility, labels, model state and topology against frozen source at crossover boundaries, constant plateaus, both division windows, backwards/repeated seeks and externally transformed roots. Keep all existing science regressions.

### 2. Evaluate only the exact x half of the scalar field

`germCellMembrane.js:update` evaluates 70,395 nodes (65 × 57 × 19), with three square roots at each node. Every x contribution uses `abs(x)`; x coordinates are `-4 + i/8`, exactly representable in Float32. Thus i and 64-i have exactly equal x terms in JavaScript, at every first/second transition value.

For each y/z row, compute i=0..32 and copy the already-rounded Float32 field result to i=64-i. Keep the complete field, gradients, grid resolution, cell/tetrahedron traversal, normal computation and emitted buffers unchanged. Scalar evaluations become 35,739, and square roots 107,217 instead of 211,185. This halves the scalar-evaluation term, not necessarily total update time. All other work remains O(N + cells + emitted vertices).

Validation: frozen/current complete position and normal buffers (including unused zero tails), draw ranges, bounds, topology and irregular-seek outputs must be bit-identical at ordinary and boundary field states. Do not mirror output normals or triangle emission, since that changes sign/ordering behavior. Do not assume analogous y symmetry: the retained horizontal bridge depends on y-cy.

## Additional concrete candidates, not authorized for this change

1. **Lazy grid gradients:** `germCellMembrane.update` computes gradients for all 70,395 nodes before finding active cells. Derive the same central/one-sided differences on first use of an uncached crossing-edge endpoint and retain the Float32 store before normal interpolation. A generation stamp avoids stale gradients across fields, with shared results for both leaflets. Gradient work changes O(N) to O(U), U being the actually used endpoint nodes; U has not been measured. Exact arithmetic and output traversal must stay unchanged. Validate bit-identical normals, boundary nodes and epoch rollover.
2. **Sparse scratch reset / output-tail reset:** `positions.fill`, `normals.fill` and two `edgeCache.fill` calls clear about 8.26 MB per moving update. Every emitted prefix element is overwritten, and fresh edge-cache entries only refer to already-emitted vertices. Keep a previous cursor and zero only `[newCursor, previousCursor)` after a shrinking update; initially zero buffers and induction preserve the entire unused tail exactly. Replace cache clears with per-layer generation stamps or reset only touched keys. Keep cache first-occurrence order and Float32 reuse unchanged. Validate full-buffer equality after grows, shrinks, zero-sized outputs and arbitrary seeks. Stamp memory tradeoff is about 1.88 MiB for `count*7` Uint32 entries.
3. **Cache local query matrices without cancelling operations:** meiosis currently performs 130 `axisPoint` calls per update (8 exchange queries + 2 chiasmata + 30 synapses × 4), plus 8 attachment queries. Current Three `localToWorld` and `worldToLocal` each update ancestors, and `worldToLocal` inverts the same root matrix each time. Cache the root inverse once per update and each chromatid world matrix after its transform update, retain the same two sequential `applyMatrix4` operations, and pass reusable output vectors. Avoid direct local-matrix shortcuts if bit equality is required. Cache fixed chromosome pair references instead of 30 `.filter` allocations and 2 `.find` calls per frame. Validate translated/rotated/nonuniformly scaled parent chains and exact world anchors.
4. **Cache deformation constants:** `setDeflection` repeatedly reloads unchanged original Float32 instance matrices, transforms the same ±.5 endpoints, computes the same radius and piecewise displacement weights. Precompute those values once from the saved Float32 arrays into Float64 tables, preserving the existing expression order. Changed-deflection output remains O(V+I), with fixed reconstruction/decomposition removed. Float64 tables are necessary; using original pre-Float32 construction values would not be equivalent.
5. **Avoid duplicate bounding-box scans:** current Three `BufferGeometry.computeBoundingSphere` rescans all positions to derive a box even immediately after `computeBoundingBox`. For these non-morph ordinary geometry buffers, a scoped helper can use the exact existing box centre, then perform the same ordered radius scan. Bounds work decreases from three vertex passes to two with identical sphere output. Do not substitute a looser conservative sphere if exact full-state equality is the gate. `finish(InstancedMesh)` can also fuse box and sphere loops, but must read back the stored Float32 instance matrix and preserve sphere-union order; using the unrounded construction matrix changes bounds.
6. **Exact-value cache for mitotic membrane shape:** `divisionShapes.cell.shape` rebuilds both 65 × 41 vertex shells, normals, bounds and 128 cut-edge instances on every update even when `(pinch, elongation, axis)` is unchanged. Cache the exact argument tuple. Constant pre-furrow and terminal plateaus then cost O(1); changed shapes are identical. This is supported by source, but lower priority than meiosis given the prior 1.4 ms p95. A hidden flag alone is not a valid skip because full-state seeking remains deterministic.
7. **Precompute fixed trigonometry:** `setBundle` repeats sin/cos for static strand/segment indices; `contractileRing.fitContour` repeats the same 100 centre angles and nine radial angles; infection `materialDuplex.setTransfer` repeats fixed material/radial phases. Cache Float64 results from the exact original angle expressions, preserving multiplication/addition order. For infection this removes repeated trigonometric calls across 2 × 1,441 × 7 surface vertices without changing segments, route sampling or normals. Validate complete Float32 buffers; do not silently introduce Float32 lookup quantization.
